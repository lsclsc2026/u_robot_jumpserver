# 安装与接入

[返回 README](../README.md) · [配置参考](配置参考.md) · [离线镜像](离线镜像.md)

本文命令为未来维护时的操作说明，本次整理未执行。示例 `192.0.2.10`、`100.64.0.10`、`100.64.0.20` 不是实际目标，必须先替换。

## 1. 服务器准备

历史服务器是 Ubuntu 22.04 x86_64，镜像平台为 `linux/amd64`。运行数据使用内部 ext4；历史安装器要求至少 20 GiB 可用空间、特定 exFAT U 盘挂载及固定 UUID。ARM64 机器人可保存资料、作为资产接入，不应直接原生运行这些 amd64 服务器镜像。

准备独立服务器、Docker 与 Compose v2、Tailscale 访问条件、DNS/TLS 证书、存储与备份位置；具体版本和容量应按设备数量、会话并发和录像保留量确定。源码未提供完整依赖锁定环境或经本轮验证的一键部署入口。

## 2. 新服务器安装路径

仓库保留 [官方安装器目录](../upstream/jumpserver-installer-v4.10.19/README.md) 及 [配置模板](../upstream/jumpserver-installer-v4.10.19/config-example.txt)。复制到实际服务器工作目录后，由管理员按模板填写安装目录、数据库、Redis、域名、TLS、端口和组件开关；新安装在运行时生成密钥，迁移恢复必须保持原密钥。使用安装器 `jmsctl.sh` 的 `install` 与 `start` 流程时，先核对其选取的镜像、配置和现有数据目录。

```bash
# 在实际服务器的安装器目录中执行；先完成配置审阅和镜像准备。
sudo ./jmsctl.sh install
sudo ./jmsctl.sh start
```

此官方流程与历史笔记本自定义六/七服务部署并不相同。官方默认配置可能启用更多组件或不同数据库镜像；若要求精确重建，须按原脚本中的 `SERVICES`、`COMPOSE_FILES`、`public_config()` 和后续 LAN/Lion 变更逐项建立配置。不能假定七个离线镜像满足安装器所有默认组件。

## 3. 原服务器专用脚本的材料与顺序

`install-jumpserver-laptop.py` 固定校验主机名、用户、Tailscale 地址、USB UUID、内部文件系统、镜像内容和归档哈希。它会拒绝既有安装/数据及未预期的容器。移植时修改这些配置需要人工审阅，不能删除校验后直接运行。

其原工作区结构如下；本仓库没有自动复制到这些系统路径：

```text
/home/ksxq/jumpserver-deployment/
├─ downloads/jumpserver-installer-v4.10.19.tar.gz
├─ images/manifest.json                  只含最初五个镜像
├─ images/*.tar
├─ lion-image.json / ansible-image.json  后续扩展需要
└─ bin/crane                            历史下载辅助工具
```

初始脚本从固定归档创建配置、载入五镜像、初始化数据库和管理员、生成 TLS 与 Compose 包装器；随后历史变更由 `enable-jumpserver-lan.py`、`enable-jumpserver-lan-ssh.py`、`add-jumpserver-executor.py`、`enable-jumpserver-gui.py` 完成。它们有固定路径和校验，只在核对实际部署状态后选择所需步骤，不能按列表全部重跑。

原始安装器归档未入 Git，精确字节副本仍在本机交接包 `upstream/installer.tar.gz`；重新打包仓库目录通常无法满足原脚本的 `ARCHIVE_SHA`。镜像同理，重新下载/保存的 tar 可能字节不同，参见离线说明。

## 4. 新 Ubuntu 下位机准备

通用脚本显式仅接受 Ubuntu 22.04 和现有非 root Linux 开发账号。确认设备 GNOME、JetPack/架构、开发目录、已有 xrdp/NoMachine、tailscale0、系统防火墙和可用的现场恢复入口。已有设备无需重装。软件安装依赖 apt 软件源；首次 Tailscale 安装依赖官方 HTTPS 安装脚本且未固定其内容版本。

将 `code/local` 中三个通用脚本放在同一目录，用实际开发账号发起：

```bash
# 下面变量均为示例；替换后再用于实际设备。
EDGE_DEV_USER=developer
JMS_TAILNET_IP=100.64.0.10
EDGE_ASSET_NAME=edge-01
sudo python3 edge_wizard.py --user "$EDGE_DEV_USER" \
  --bastion-ip "$JMS_TAILNET_IP" --name "$EDGE_ASSET_NAME"
```

向导会安装/启动 Tailscale、等待浏览器授权、要求确认服务器可达设备、先检查后安装桌面，最后输出页面配置与收尾命令。若加入错误 tailnet，不自动退出或迁移；先核实组织和访问策略。页面资产、账号、授权、录像验收仍需人工完成。

需要单独处理桌面时：

```bash
sudo python3 setup_edge_desktop.py --user developer \
  --bastion-ip 100.64.0.10 --name edge-01
# 上一条检查通过、确认安装计划后才添加 --apply。
sudo python3 setup_edge_desktop.py --user developer \
  --bastion-ip 100.64.0.10 --name edge-01 --apply
```

默认检查也会读取实际服务和网络状态，因此不属于本次允许执行的静态发布检查。缺少 GNOME 时需明确加 `--install-gnome`；已有不同 `startwm.sh` 时先查看并备份，确认后才加 `--replace-startwm`。

## 5. 桌面配置内容

脚本安装 OpenSSH、curl、证书、Python、nftables、xrdp、xorgxrdp、dbus-x11；按需安装 `ubuntu-desktop-minimal`。加入 `jms-rdp-users` 与 `ssl-cert` 组，xrdp 只监听本机 Tailscale IPv4 的 3389，启用 TLS，拒绝 root 桌面。它逐节修改 INI，保留 sesman.ini 的重复 `param=` 行。

用户目录生成 Ubuntu GNOME `startwm.sh`，systemd 添加等待 Tailscale 地址的启动覆盖。配置备份在 `/var/backups/jms-edge-*`。失败时恢复已备份配置、停止 RDP；已安装软件包和组成员变更不会自动撤销。

## 6. 交付顺序

按 [用户资产与授权](用户资产与授权.md) 创建两个资产；实际验证终端、桌面、项目环境、个人审计记录及回放后，按 [使用手册](使用手册.md) 开启临时防火墙，再从新会话确认并持久化。最后单独安排重启、NoMachine 连接失败、录像保留和恢复验收；任何成功提示均不能替代这些项目。
