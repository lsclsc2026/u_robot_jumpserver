| 位置 | 用途 |
|---|---|
| `/usr/local/sbin/jumpserver-laptop-compose` | 历史部署的 Compose 包装器，含自定义覆盖 |
| `/opt/jumpserver/config` | 私有配置、证书、密钥 |
| `/opt/jumpserver-installer-v4.10.19/compose` | 上游模板与实际部署覆盖 |
| `/data/jumpserver` | 数据库、审计、运行数据 |

| `/home/<开发用户>/startwm.sh` | GNOME 会话启动 |
| `/usr/local/sbin/jms-edge-wait-tailscale` | 开机等待 Tailscale 地址 |

现有历史服务器日常服务状态入口为：

```bash
sudo /usr/local/sbin/jumpserver-laptop-compose ps
```

若包装器缺失，先查实际 Compose 与配置，不能直接重跑初装脚本“修复”；原交接时该文件及 `laptop*.yml` 因权限未完整采集，仓库不伪造当前实值。

## 故障定位

| 现象 | 优先核对 |
|---|---|
| 平台能登录但资产不见 | 用户组、节点/资产授权、系统账号和协议、规则有效期 |
| 连接性自动化失败但 Web SSH 正常 | Ansible executor 镜像、任务细节与数据目录映射 |
| 网页或 Koko 从 LAN 不可达 | 实际 LAN 地址、端口映射、证书 SAN、网络策略 |
| 桌面黑屏 | xrdp/sesman 日志、GNOME 启动、同账号现存桌面会话 |
| Xorg 参数异常 | INI 重复 `param=` 是否完整；恢复本机对应备份 |
| xrdp PID/启动超时 | systemd 启动方式；历史前台模式修复仅在同类故障时考虑 |
| `.xsessionrc` shell 语法错误 | 用户启动环境是否将 Bash 内容交给 sh |
| 桌面没有原项目/环境 | 实际 Linux 账号、HOME、PATH 和项目启动方式 |
| ping 成功但直接 SSH 超时 | SSH/RDP 限制可能正按预期工作；仍需确认新网关会话 |
| 试运行后规则消失 | 自动回滚期限到达，尚未完成 confirm |
| 交互延迟 | 浏览器、WebSocket、服务器资源、tailnet 直连/中继状态 |

诊断脚本仍会访问 Docker、数据库、日志或实际网络；名字包含 `diagnose` 不代表发布整理时可以执行。输出可能含真实账号、IP、事件和日志片段，仅在受控目录存放。

## 账号恢复

`recover-jumpserver-admin.sh` 是管理员本地交互恢复工具，通过容器内交互流程修改平台管理员密码并处理相关登录阻塞。执行前核对实际容器和恢复权限；新密码只在交互提示中输入。恢复事件应记录操作人和时间，记录中不含凭据。

操作员诊断现在要求运行时输入名单及待检查口令，查询结果不修改密码。它是故障定位工具，不能用于生成或发布用户凭据表。

## 备份与恢复

数据库包含用户、资产、授权以及加密凭据，采用 PostgreSQL 一致性导出或符合数据库要求的备份流程。原安装器保留 `backup_db`/`restore_db` 对应脚本，使用前核对本部署数据库类型、参数与目标。运行中的 PostgreSQL 数据目录不能直接随意 tar 后宣称可恢复。

将数据库与 `/opt/jumpserver/config` 中原密钥、TLS 私钥、Compose 覆盖、录像及文件存储纳入同一恢复目标；凭据与数据备份分离受控保管，记录版本与时间。在隔离环境验证还原后的平台账号、资产、加密凭据解密和回放，再规划切换。恢复已有环境不能重新生成 `SECRET_KEY` 来替代原值。

原 USB 挂载脚本不代表定时归档已实现。容量阈值、保留策略、掉盘保护、告警与还原演练仍待单独实现/验收；数据库、录像和完整日志均不在 Git 仓库内。

## 采集工具

`tools/collect_host.py --role server|edge --out <本地输出.zip>` 按白名单采集文件，并运行本机状态命令。代码/日志白名单仍可能包含个人信息，配置正则脱敏不是完整数据防泄漏保证，输出必须再次审核后才能分享。它不是本次已执行的验证证据。

`tools/send-to-unitree.sh` 保留历史固定交接包路径与 SCP 目标，运行会传输文件。新环境先检查源码并按真实目标调整；这不是自动安装工具。
