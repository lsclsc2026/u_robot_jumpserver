# 使用手册

[返回 README](../README.md) · [安装](安装部署.md) · [运维](运维手册.md)

## 同事日常使用

在公司网络内打开管理员提供的 HTTPS 域名/地址，核验证书后用个人 JumpServer 账号登录工作台。选择授权终端资产进入 Web SSH，选择对应 `-desktop` 资产进入远程桌面。平台自动使用授权的资产账号，不要求同事知道设备口令。

本地 SSH 客户端通过管理员提供的堡垒机地址和 2222 端口进入 Koko，再根据网关提示选择资产。示例仅表示入口格式：

```bash
ssh -p 2222 operator-example@bastion.example.invalid
```

会话内确认实际 Linux 用户、HOME、项目目录和开发环境后再开展工作；同名平台用户不意味着同名系统账号。结束时正常退出会话，不把浏览器关闭当成应用进程一定已终止。桌面与终端分别记录，桌面录像不是逐条 exec 或文件 diff 审计。

## 向导的人工停顿

| 阶段 | 管理员需要完成的事 |
|---|---|
| tailscale | 浏览器授权加入正确 tailnet，检查堡垒机可见性；向导不自动迁移现有组织 |
| desktop | 阅读检查结果，明确批准安装桌面依赖及配置变更 |
| assets | 建立两个资产、录入系统账号、授权个人用户/用户组，实际确认连接与回放 |
| finalize | 从 JumpServer 新开 SSH 会话执行收尾，避免在直连会话中把自己断开 |

输入 `q` 可在向导暂停点退出，之后通过 `--from-stage` 继续；退出不等于回滚已经安装的软件。输出 `WIZARD_HANDOFF_READY` 仅表示已交给收尾流程。

## 带定时回滚的收尾

仅在 SSH、RDP、开发目录和审计已经人工通过后，从 JumpServer 资产终端运行以下未来操作。示例地址需替换：

```bash
sudo python3 edge_finalize.py apply --bastion-ip 100.64.0.10 --minutes 15
```

脚本检查 tailnet、已有规则、事务状态和交互终端，要求输入 `APPLY`。先安排自动回滚计时器，再应用只允许堡垒机访问 SSH/RDP 的规则。期间 NoMachine 暂时保留。

在时限内另开新的 JumpServer SSH 与桌面会话，确认都可用，同时确认 LAN/直接 Tailscale 的 SSH/RDP 失败；旧会话仍可用不能替代新连接测试。通过后在新会话运行：

```bash
sudo python3 /var/lib/jms-edge-finalize/manage.py confirm
```

再次确认后输入 `VERIFIED`；脚本关闭 NoMachine 并设为手动启动，核对状态，启用 `jms-edge-final.service` 持久化规则，最后取消回滚计时器。剩余不足 30 秒、NoMachine 状态不符等会阻止提交。脚本检查不能替代实际 NoMachine 客户端连接失败验收。

状态和主动撤销：

```bash
sudo python3 /var/lib/jms-edge-finalize/manage.py status
sudo python3 /var/lib/jms-edge-finalize/manage.py rollback
```

超时会自动回滚自己的防火墙表；不会自动重新启动 NoMachine。确认后的重启、网络变化和其他远程入口需单独验收。原首台 `restrict-edge-ssh.py` 是 10 分钟历史流程，不与通用 15 分钟流程叠加。
